# Sonda exchange contract — proposed 1.0.2

[AI Social Network](ai-social-network.md) · [Canonical bundle](../../contracts/sonda/v1/manifest.json)

This is a proposal for coordinated Huginn/AIDP implementation, not a claim that the current 1.1.1 runtime supports Sonda. Publication and installation of the next minor release require acceptance of both applications. A release never deletes an existing generation automatically.

The [Python contract types](../../apps/backend/app/sonda_contract.py) are authoritative. [schema.json](../../contracts/sonda/v1/schema.json), [chat.schema.json](../../contracts/sonda/v1/chat.schema.json), the reference, manifest and synthetic fixtures are generated by `python scripts/export_sonda_contract.py`; `--check` rejects artifact drift. There is no new contract framework or dependency: export and validation use the existing Pydantic runtime. Cross-field approval/reference/fingerprint checks in the Python types supplement the portable structural JSON schemas.

## Scope and compatibility

Every exchange document carries `contract_version`, `contract_sha256`, `registry_id` and `generation_id`. UUIDs are canonical lowercase strings. The deployment binds one registry and generation through protected operator configuration; values in a message or browser request cannot select another owner. Each consumer verifies its installed binding and pinned contract before applying data.

`schema_sha256`, `chat_schema_sha256` and `reference_sha256` hash exact UTF-8 artifact bytes. `reference.py` is the exported executable reference for cross-field invariants and identity, not code to execute from untrusted messages. `contract_sha256` hashes canonical JSON of those three named hashes, including its terminal LF. This binds semantic checks that JSON Schema alone cannot express. Version 1.0.2 explicitly supersedes the unactivated 1.0.0/1.0.1 proposals and adds real budget-round availability; consumers must accept the new pin rather than silently replace an accepted hash. The manifest also records fixture hashes. Canonical encoding means UTF-8, recursively sorted object keys, no insignificant whitespace, unescaped Unicode, finite numbers and one terminal LF. Hash message/entry **raw bytes** against their ledger receipt; do not reserialize them first. Fixture bytes provide portable hash examples. Size is at most 4 MiB per document; duplicate keys, credentials, unknown fields and excessive nesting are rejected. Nothing fetches external schema references.

Different registries never share identifiers, cursors or report state. A new generation invalidates old chat history and native session derivation, even when the endpoint and OCI identity stay the same. A changed fingerprint under an existing message identity is a conflict, not a new event.

| Kind | Producer | Payload |
| --- | --- | --- |
| `configuration` | Huginn | Full immutable configuration revision, reviewed connectors, sources, queries, criteria and budget policy |
| `budget_round` | Huginn | Revisioned live round, configuration revision, explicit opening/expiry, open/closed state and conservative available money/items |
| `observations` | Huginn | Up to 100 normalized observations for one source/query/execution, capture configuration revision and budget round |
| `execution_result` | Huginn | Result or refusal of a capture/research request, observation message IDs, actual cost when known and coverage |
| `investigation_request` | AIDP | Bounded request referencing an approved query revision, case, budget round, expiry and supporting evidence |
| `report` | AIDP | Revisioned summary, deterministic indicators, evaluations, evidence, references and coverage/limitations |
| `proposal` | AIDP | Pending typed criterion/query change, base configuration revision, author and rationale |
| `processing_receipt` | AIDP | Durable applied/rejected result of an inbound message |
| `stream_entry`, `stream_head`, `consumer_ack` | See transport | Sequential delivery and processing receipts; no business authority |

## Reviewed sources and human approval

Huginn alone approves configuration. Each snapshot has contiguous `revision` / `previous_revision`; each managed record has a stable UUID, revision, origin `operator|agent`, author and approval. An agent-authored record retains its origin after a human approves it. Only approved records may be active. A proposal always remains pending/draft and cannot activate itself; approval in Huginn produces a new configuration snapshot referencing `proposal_id`. A stale proposal must be reconciled against its base revision before approval. `proposal_decisions` defaults to an empty list and contains decisions made in this revision: proposal ID, approved/adjusted/rejected outcome, operator, time, configuration revision and optional reason. Approved/adjusted decisions require the matching approved record/operator/time; rejection cannot activate a change. Replicate terminal decisions to AIDP rather than leaving a rejected proposal pending forever. Earlier decisions remain in earlier immutable snapshots and are not resent as a growing history list.

Each effective Actor/build/operation has a separate connector. `operation` distinguishes account posts, search posts, comments, pages and mapped indicators, and must match its single effective mode. The connector pins its reviewed input-schema hash, output mapping, cost ceiling when known and allowed research fields. `catalog_sha256` uses `catalog_fingerprint`: sort DTOs by connector ID and normalize `reviewed_at` to six-fractional-digit UTC `Z` before canonical encoding. Equivalent timestamp representations therefore have the same hash. A source references a connector revision; it never overrides its Actor. Browser/model payloads cannot supply arbitrary code, Actor endpoints or credentials.

Sources use `social|news|public_web|economics`; social platforms are the six existing networks. Non-social sources require a nonempty `allowed_domains` list. Hosts are lowercase ASCII/punycode, exact matches, without wildcard; list subdomains explicitly. Huginn validates public HTTP(S) targets without credentials, private/local destinations or unapproved redirects, and maps restrictions into each reviewed Actor's supported crawl settings. For pages/indicators, a research target override must stay on an approved host. Account/search targets follow their reviewed connector's operation and input schema. AIDP requests refer to `query_id` and revision, never a new Actor.

A criterion selects approved `source_ids`; optional `query_ids` refine that selection. No query list means all eligible queries of those sources, not all sources. `threshold` starts at 0.80 and must be evaluated with labelled positive/negative examples. The score is a model relevance score, not a calibrated probability or a newly trained ML model. Research additionally requires both `Criterion.allow_research` and `Query.research_allowed`; both are opt-in in Huginn.

Configuration snapshots are retained by revision. Captured observations use their capture revision, source revision and query revision, even if a later save arrives before the capture finishes. Additional paid work must use the **current** approved configuration, unexpired budget round and request; an older snapshot cannot bypass a pause or revocation. A stale request returns an explicit refusal/result. AIDP does not silently reinterpret old observations under new rules or start a full historical re-evaluation on every save.

## Object Storage transport

Use the existing namespace, protected artifacts bucket and bound source bucket/prefix. No payload supplies an arbitrary bucket, object URL, PAR or file path.

For each direction, define the protected stream root in the artifacts bucket:

```text
ai_social_network/exchange/v1/registries/{registry_id}/generations/{generation_id}/{direction}/
    messages/{message_id}.json
    entries/{sequence:020d}.json
    head.json
    ack.json
```

`direction` is exactly `huginn_to_aidp` or `aidp_to_huginn`. **Observation message bodies alone** live in the selected source bucket, at `{source_prefix}exchange/v1/registries/{registry_id}/generations/{generation_id}/huginn_to_aidp/messages/{message_id}.json`. This keeps capture in Landing without duplicating its body. Their protected stream entry includes `message_kind=observations`, hash and length; the consumer derives the source location from that kind and its installed binding. Other message kinds, entries, heads and acknowledgements stay in artifacts. The digest in the protected entry detects tampering with a Landing body. A source-bucket object cannot grant configuration approval.

There is one serial publisher for each direction/registry/generation; five concurrent Apify jobs enqueue results but never independently allocate stream sequence numbers. Publishing is:

1. Persist the sender's durable outbox operation and stable message UUID.
2. Create the immutable body with `If-None-Match: *`. Existing UUID/hash equality is a retry; differing bytes are a hard conflict.
3. Create the immutable entry at the next contiguous sequence, with body hash/bytes and predecessor entry hash. Sequence one has no predecessor.
4. CAS `head.json` using its prior ETag, or create with `If-None-Match: *`. Publish only the already-written entry. Recover the same pending publication after a crash; never overwrite a conflicting entry.

Huginn polls outbound heads every minute. A consumer reads only entries committed by the head, in order, and verifies scope, predecessor hash, body hash/length, kind and contract. A missing/corrupt entry stops cursor advancement. Unreferenced orphan bodies do not become inputs. An invalid business message with a valid transport/scope gets a durable rejection receipt and may advance `last_processed_sequence`; it never changes the last accepted configuration or becomes a successful empty dataset. Structural scope/hash corruption cannot be acknowledged as applied.

Write Gold/business receipts durably before CAS-updating `ack.json`. A crash before acknowledgement replays the same operation, whose business keys are idempotent. The acknowledgement is written by the receiver, and means terminal processing (applied or rejected), not that every message was accepted. Publish rejections through `processing_receipt`. Outbox/receipt state is generation scoped. No recursive listing is needed for normal exchange; sequence cursors bound work per poll.

## Observation and investigation identity

The executable reference is `observation_fingerprints` in the Python contract; fixtures contain expected outputs. Normalize human content strings to NFC, preserving opaque provider IDs and URL path/query code points exactly. URL identity lowercases scheme/IDNA host, removes default ports and fragments, uses `/` for an empty path and preserves path/query semantics. Do not strip unknown query parameters. Connector-specific extraction/canonicalization changes require a mapping revision.

- Social document identity hashes `[1, document_type, platform, parent_document_key, provider_id]`; posts have a null parent, comments require a parent. Provider IDs and platform are mandatory.
- Page/indicator identity hashes `[1, "url", canonical_url]`, independent of source/query/run. Page and mapped-indicator views of a URL therefore refer to the same document.
- Business content hashes the normalized fields implemented by that helper: identity metadata, canonical URL, title/text/author, UTC publication time, nullable metrics, mapped indicators sorted by key, and capture scope. UTC times use six fractional digits and `Z`. Capture time, query, execution and wrapper metadata do not change the business fingerprint.
- `observation_key` hashes `[1, document_key, content_sha256]`. Changed content/metrics creates a distinct version. Repeated unchanged capture updates discovery/last-seen provenance, without another observation or inflated indicators.
- Quote evidence hashes `[observation_key, exact_quote]`; the runtime additionally verifies that the quote and reference exist in the committed observation. It never trusts a model-created URL as proof.

Keep discovery provenance separately for every query/execution that found a document. Indicators count distinct logical documents/observations according to their documented metric; never count discovery rows or historical versions as distinct publications. Unknown counters remain NULL, not zero. Economic values require an explicit reviewed mapping, unit and period; use decimal strings with at most 26 integer and 12 fractional digits, not binary floats.

A case key hashes `[criterion_id, criterion_revision, case_scope_key, UTC_window_start]`; its window is the approved `case_window_hours`. Replaying an evaluation resumes the same case. Evaluation identity also binds observation content, rule revision/hash, model revision and prompt version. No synthetic ML training is implied. Errors have no score; successful verdicts must agree with their threshold and quote evidence.

A research request UUID is deterministic for its case, planned step, approved query revision and target; an execution retry reuses it. Huginn alone reserves/spends budget and starts/reconciles Actors. `round_budget_microusd`, `research_reserve_microusd` and `max_charge_microusd` are integer millionths of USD. Reserve must fit the round; per-query, per-round, result-count, expiry and five-job concurrency limits all apply. Missing price/reservation is not permission to spend. Uncertain starts remain reconciliation work, never an automatic new paid start. Budget exhaustion produces a report using available evidence with explicit limitations.

`budget_round` is produced from Huginn's durable coordinator ledger, not inferred from capture times. Its revision is monotonic per round. Publish opening, reservations/known spending and closure, including explicit `opened_at`/`expires_at`, current configuration revision, conservative `remaining_microusd`, `research_remaining_microusd` and `remaining_items`. Unknown availability is NULL, never zero or an assumed full allowance. Uncertain executions retain their reserved caps. AIDP only plans requests from a known, open, unexpired compatible round with known price/availability; each request is still an intent, not a spending grant. Huginn rechecks and reserves atomically against its current ledger. A stale advisory snapshot can cause refusal, never bypass live limits. Ephemeral concurrent-slot counts are deliberately not replicated: the broker queues work and enforces five live jobs itself.

## Gold model proposal and efficient access

Delta remains the engine. No relational foreign-key enforcement is assumed: validate same-registry/generation parent references before MERGE, and recheck at publication. These proposed tables are not created by exporting this contract:

| Domain | Proposed grain | Physical approach |
| --- | --- | --- |
| Configuration | `ai_social_registry` snapshots; source/query/criterion revisions | Small unpartitioned tables with registry/generation/revision predicates; no sparse partition per UUID |
| Observations | `ai_social_document_current`, `ai_social_observations`, `ai_social_discoveries` | Current by low-cardinality kind/platform; versions/discoveries by UTC observation month; MERGE only affected keys/partitions |
| Detection | `ai_social_evaluations` | Idempotent input/rule/model/prompt key; month partition and rule predicates; no model call for an already completed identical evaluation |
| Research | `ai_social_investigations`, `ai_social_evidence` | Stable case/evidence keys, bounded pending-case scans, no arbitrary model SQL |
| Serving | `ai_social_reports`, `ai_social_proposals`, compact daily aggregates | Published revision and state predicates; deterministic counts with evidence coverage |
| Recovery | Exchange receipts/outbox and `ai_social_publication` | Sequential cursor, exact serving Delta versions, retry journal; ack only after committed business effects |

Reuse the existing coherent-publication/dirty-journal pattern rather than claiming cross-table Delta transactions. Gold and control locations are dedicated to the registry/generation. Derive locations from the installation binding; preserve private configuration, shared credentials, other modules, buckets and platform. Measure scanned bytes/file sizes/latency before adding serving indexes or changing partitions. This proposal is not a massive-volume benchmark.

## Chat and human-facing DTOs

The v2 native input is exactly `{version:2,question,search_context:{registry_id,generation_id,config_revision,source_ids,query_ids}}`. Questions remain 1–500 characters. Selections are references resolved against approved Gold configuration, not a copy of every rule. Empty selection arrays mean no additional filter in the bound generation. The proxy binds these values to its authenticated user. Preserve v1 for legacy deployments, but never silently accept unscoped v1 input in a new Sonda generation. Session/memory namespace and browser history must bind the generation.

Native answers retain `answer`, safe `sources` and optional data-only `visualization`; add bound registry/generation/configuration metadata for proxy verification. Reports expose title/summary, indicators with value/unit/method/coverage/evidence IDs, evidence with URL/quote, and coverage limitations. Huginn may project `label→name`, `evidence→references`, and `quote→excerpt` in its UI DTO without changing the interchange artifact. Proposal diff/approval UI belongs to Huginn; AIDP only emits a pending typed change and base configuration revision.

## Reset and acceptance boundary

The approved one-time reset is an explicit operator operation for an inventoried deployment, never an installer side effect. Pause all producers, chat and investigations; reconcile active/uncertain work; exchange both inventories and agree registry/generation IDs before deleting. Delete the exact owned source objects and every object version, dedicated Delta/control data and checkpoints, and native agent memory through supported APIs. Do not touch provider-private/shared tables, other resources or bucket/platform identities. Verify absence rather than accepting time-travel-recoverable DELETE as purge. Retention, sharing or unsupported memory cleanup blocks completion and leaves the flow paused. No backup of capture or memory is created; metadata inventories and deletion receipts are retained.

After empty-state verification, bind a new generation and publish its approved configuration. Old-generation messages cannot replay into it. Test positive/negative labelled semantics, budget refusal, uncertain execution reconciliation, same-content/multi-query deduplication, changed-content versions, resumable case/report production, stale proposals and operator-only approval. Fixtures are synthetic and cause no Actor starts; real capture/model/native results must be reported separately. Publication of a new release requires both applications' integrated acceptance.

## Native integration under development

The contract bundle is frozen at 1.0.2. The source modules in this branch are not
an activated deployment or a released package. In particular, the installed
legacy chat endpoint does not yet implement the v2 scope confirmation.

`sonda_exchange.py` uses create-only bodies/entries, an ETag-conditional head and
acknowledgement, and a persisted `PreparedPublication` supplied by the runner's
outbox. A producer must save that reservation before attempting publication and
retry the same operation after an unknown result. One generation writer owns
each direction. Consumers verify a bounded contiguous window, its predecessor
and the committed head tip; a backlog larger than a window remains drainable.
Malformed transport or scope stops at the offending entry. Business-invalid
payloads with verified envelope identity can receive a durable sanitized
rejection receipt; they never become successful empty data or retain secrets in
the rejection journal. Acknowledgement follows committed effects and receipt
outbox, including rejection.

The investigator ships one `study_case` pipeline; the unused cumulative study
implementation was removed. Evaluate at most 100 pending
observations for one case, commit their verdicts in Gold, then reload report
work from the published Delta versions. SQL computes complete distinct-document
totals, current metrics and missing coverage. The model sees a bounded selection
of complete citations and those computed facts; a sample cannot supply a total.
Gold operational checkpoints contain case identity, input fingerprints, revision and
bounded request/proposal references, without copies of accumulated publications
or configuration history. Version/predecessor checks prevent stale case writes.
This is a design for bounded processing, not evidence of a massive-volume SLA.
Measure Delta scanned bytes, latency and file sizes under representative load
before promising throughput or changing partition/compaction policy.

Document dates and numeric counters precede long text/URLs in the physical
schema, so the first 16 statistics columns cover the query predicates without
collecting expensive long-string statistics. History/discovery month partitions
remain coarse; current documents use low-cardinality kind/platform partitions.
Free-text containment still scans the selected scope: constrain dates and sources
and measure before introducing a supported search index. For frequent small
writes, validate native Delta capabilities before enabling auto compaction in the
same writer; Delta documents it from version 3.1 with a default 128 MB target.
Compaction does not justify vacuuming pinned serving versions or automatic
retention-zero cleanup. See the [Delta optimization reference](https://docs.delta.io/optimizations-oss/).

`sonda_model.py` restricts inference to evaluate/plan/report/propose roles with
structured output. Source content is untrusted evidence. The model cannot choose
Actors, execute SQL, approve configuration or spend budget. The installer must
resolve the selected model's actual OCI revision; the prompt revision hashes
the installed role instructions. Input context has a byte limit and errors
retain unknown scores rather than fabricated zeroes.

The native investigator reads immutable work from the bound generation's
protected control prefix. Invocation accepts only a work UUID and SHA256, not
an arbitrary URL or credentials. It persists a create-only result and resumes
through the existing AI Lakehouse checkpoint client with a generation/work
namespace. Gold remains the authority for business state, approval, evidence,
budget and publication; a native response alone cannot commit a report.

Oracle's incoming `checkpoint_ns=default` is normalized to LangGraph's root
namespace before reading graph state. The authenticated session and agent context
are retained; only checkpoint storage receives the generation prefix. Other
external subgraph routes are rejected. Both native entry points use this boundary.
An explicitly selected network uses an ungrouped aggregate so an empty population
returns a verified count of zero; missing engagement metrics remain NULL.

The runner records a conditional per-case pending-work pointer before inference.
An unknown HTTP outcome resumes that exact immutable work even if new evidence
for the same case arrives meanwhile. Its result is applied idempotently before
the pointer advances. Native node checkpoints temporarily include the bounded
work projection; the terminal state clears work and result after the immutable
result object commits. This is distinct from the compact operational state in
Gold. Clearing terminal state does not purge earlier native checkpoint versions;
retention requires the supported memory API and an explicit policy.

Before consuming another inbound batch, the single writer reconciles its pending
native work against the original Gold input. If that outcome is still unknown,
the run reports deferred and leaves inbound messages unacknowledged. This avoids
invalidating an in-flight report with a newer input revision, at the cost of
delaying ingestion while the native dependency remains unavailable.

Immutable work/results and Gold effects are idempotent; provider inference is not
transactional with their checkpoints. A process failure before a verdict/result
commits can repeat a model call on recovery. This is not a guarantee of exactly
one billed inference per observation. Monitor OCI model/compute consumption
separately: the Huginn capture budget controls Apify, not those OCI charges.

A protected generation binding fences ingestion and inference. Missing or
inconsistent binding or incomplete reset keeps the service paused. With an
explicit bootstrap fence, a paused manual job can create/verify tables and apply
configuration messages only; it stops before budgets or observations and never
investigates. An operator validation window can permit native inference for up to
one hour while production remains disabled. Expired windows fail closed. Full
scheduled processing requires enabled and integrated_acceptance together.
Enabling production is an explicit final operator step; installing a release does
not delete data or silently claim acceptance of an unverified generation.

## Installer preparation and release boundary

`SondaAidpClient` is the application installer for component 1.2.0. It resolves the
selected OCI model by its exact server-configured ID and actual active catalog
revision. An unversioned alias, another identity or inconsistent storage binding
stops preparation before capture. Spark uses its injected secret API; AI compute
uses the importable API. Both reuse the existing shared credential and bound region.

An operator first publishes the approved Huginn configuration and provisions one
protected `binding.json` at the generation control prefix. The document declares
the registry/generation, contract pin, storage/source/identity fields, verified
reset, required `bootstrap_config_revision`, and explicit operational flags. It
contains no private key. Initially `enabled=false`, `bootstrap=true`, and
`integrated_acceptance=false`. The one-time reset itself is never an installer
operation. Initial discovery is bounded to 20,000 operational objects; an existing
generation reads its exact binding key rather than scanning accumulated work.

Preparation keeps the five-minute job paused, runs configuration-only bootstrap,
then verifies a fresh runtime receipt: all 26 tables, the required configuration
revision and a hash-bound map of committed Delta serving versions. A successful
job without that receipt is insufficient. Table descriptions explain each grain
and purpose. SQL namespaces use strict plain identifiers compatible with the
native catalog; source bucket names may still contain hyphens.

The installer preserves the `ai_social_network` chat UUID and deploys a separate
`ai_social_network_investigator` on the existing dedicated AI compute. Deployment
and redeploy markers are persisted independently, including pending outcomes. The
chat retains developer use access; the investigator and its files remain private
to platform administrators. The application still requires its existing operator
authorization for install/redeploy. A question cannot change a protected binding,
choose an HTTP endpoint, access another generation or activate a proposal.

Both native sources and shared contract/composer source are hash-declared in the
component pack. `render_sonda_runtime.py --check` verifies the committed package;
the compositor rechecks the bytes it actually reads. Deployment readiness,
integrated acceptance, immutable release publication and the portal update are
separate checks. This branch remains a candidate until those checks pass.
